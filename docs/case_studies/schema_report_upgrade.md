# Case Study: Schema And CI Report Upgrade

Date: 2026-05-29

This case study records a real StateBind Guard self-upgrade: moving from an
installable CLI to a versioned machine contract and CI-friendly validation
report.

## Risk

The task touched multiple similar handles:

- implementation: `statebind_handoff/statebind_handoff.py`
- skill copy: `integrations/codex-skill/statebind-handoff/scripts/statebind_handoff.py`
- schema artifact: `schemas/statebind.schema.json`
- CI report artifact: `statebind-validation.json`
- validation gate: `make public-check`
- remote verification: GitHub Actions `smoke`

A normal summary such as "finish the schema work and run the checks" would
preserve the story but not the executable bindings. That is exactly the failure
mode StateBind Guard targets.

## Result

The following gates passed:

- `python -m unittest discover -s tests`
- `make schema-check`
- `bash scripts/run_smoke_test.sh`
- `make package-check`
- `make public-check`
- `python -m pip wheel . --no-deps --no-build-isolation`
- GitHub Actions `smoke` on commit `a403afa43849c19d06ff930bef7d710246c96dd3`

## What This Proves

This proves the tool can preserve the action-relevant bindings for its own
industrialization work: implementation file, generated schema, generated report,
local gate, remote commit, and CI run.

It does not prove broad deployed-agent reliability. The next gate is a larger
corpus of real-world handoff failures and third-party workflow integrations.
